# AIDIS Lab 홈페이지

대전대학교 AIDIS Lab의 정적 홈페이지입니다. 별도 설치나 빌드 없이 GitHub Pages에서 운영하며, 새 활동의 로그인·저장은 Supabase Auth와 Database를 사용합니다.

## 다른 PC에서 작업 이어가기

새 작업은 [AGENTS.md](AGENTS.md)의 규칙과 [CODEX_CONTEXT.md](CODEX_CONTEXT.md)의 현재 상태를 먼저 읽고 실제 파일을 대조합니다. 중요한 변경 후 컨텍스트 문서도 갱신합니다. 자료 대조 근거는 [CONTENT-AUDIT.md](CONTENT-AUDIT.md)에 있습니다. Git으로 옮길 때는 미추적 파일을 포함한 커밋·원격 반영 여부를 확인하고, USB로 옮길 때는 프로젝트 폴더 전체를 복사합니다. 원본 참고 PPT는 프로젝트 밖에 있으므로 필요 시 별도 전달해야 합니다.

## 페이지 구성

- `index.html`: 홈과 주요 페이지 안내
- `about.html`: 연구실 소개
- `professor.html`: 기본 정보, 학력, 경력, 주요 연구 분야, 진행·완료 연구, 대표 논문
- `research.html`: 데이터 분석 및 인사이트 도출 / 인공지능 모델 연구 / AI 기반 소셜 플랫폼 개발
- `members.html`: 재학생·졸업생 프로필, 문의 안내
- `contact.html`: 연구실 위치, 지도교수 이메일과 유선전화
- `activities.html`: 활동 목록·유형 필터
- `activity-kpaas.html`: K-PaaS 수상 상세
- `member-*.html`: 재학생 7명·졸업생 1명의 개인 상세

메뉴 순서는 홈 → 소개 → 지도교수 → 연구 → 구성원 → 활동 → CONTACT입니다. 홈 메뉴와 AIDIS LAB 로고 모두 메인 페이지로 연결됩니다. 기존 /#about, /#professor, /#research, /#members, /#projects, /#contact 링크는 navigation.js에서 해당 페이지로 연결합니다. 프로젝트 기록은 professor.html#projects에 있습니다.

## 구성원 정보 수집과 교체

재학생/졸업생 탭은 선택한 그룹만 표시하며 기본값은 재학생입니다. 졸업생 성과는 구성원 화면에서 제외했으며 활동 페이지에서 확인할 수 있습니다. 탭 동작은 members.js에 있습니다.

실제 재학생 7명은 랩장 → 기수(오름차순) → 입학 연도(오름차순)로 자동 정렬합니다. 카드에 data-leader(랩장 1/그 외 0), data-cohort, data-entry-year를 지정합니다. 정렬은 각 그룹 안에서 members.js가 수행하며 값이 같으면 기존 순서를 유지하고 누락된 숫자는 후순위로 처리합니다. 모두 1기이며 목록·상세에 기수를 표시합니다. 목록·상세에는 사용자 확인 학과·학년을 표시하고 입학 연도는 정렬용 데이터로만 유지합니다. 한 줄 소개는 생략하며 기술 스택은 태그·관심 분야는 태그로 표시합니다. 졸업생은 5명이며 1명은 상세 페이지, 4명은 이름과 기본 이미지만 표시합니다. 기존 가상 프로필 4개는 제거했습니다.

사용자는 홈페이지 등록용으로 보내는 정보·사진을 공개 동의 YES로 처리하도록 지정했습니다. 추가 자료를 받으면 목록과 상세를 함께 갱신합니다. 이름·입학 연도·기술 스택·관심 분야·활동·링크 등 제공된 항목만 사용하며 미제공 선택 항목은 생략합니다.

- 실제 사진은 assets/members/에 6개가 등록돼 있습니다. 후속 첨부 사진의 인물 대응을 사용자에게 확인하여 모두 반영했습니다.
- 상세에 통합 기술 스택과 활동별 기간·역할·기여·논문·수상, 자격증과 실제 GitHub 링크를 반영합니다.
- 이메일은 해당 HTML에서 관리하며 인수인계 문서에 복제하지 않습니다.
- 날짜와 참여 역할, 활동 간 관계는 근거가 없으면 추정하지 않습니다.

## 미리보기와 배포

index.html을 열거나 이 폴더를 정적 HTTP 서버로 실행합니다. 모든 내부 링크와 파일 경로는 상대 경로입니다.

기존 GitHub Actions는 main 브랜치에 push할 때 사이트를 배포합니다. 로컬 파일 수정만으로 공개 사이트가 변경되지는 않습니다.

## 활동·소식·일정 등록

- 활동 목록: `activities.html`과 Supabase `lab_activities`. 새 활동은 관리자 화면에서 게시합니다. 필터 분류는 `development`(개발), `competition`(공모전·수상), `presentation`(발표·공유), `education`(교육·운영). 새 글의 상세는 `activity.html?id=게시물UUID`로 표시합니다. K-PaaS 상세는 기존 정적 파일을 유지합니다.
- 상세 취합 항목: 제목, 개인/팀 구분, 기간, 상태, 문제·목표, 진행 과정, 기술, 참여자별 역할·기여, 결과·성과, 공개 가능한 이미지와 GitHub/시연/발표 링크. 제공되지 않은 항목은 추정하지 않는다. 참여자는 실제 구성원 공개 승인 후 연결하며 예시 프로필에 성과를 연결하지 않는다.
- 메인 소식: `index.html`의 `.home-updates`에 공개할 소식 3건 이내를 최신순으로 등록하고 활동 상세 또는 공지 자료로 연결한다. 현재 수상 기록은 정확한 날짜 미제공으로 날짜를 생략했다.
- 예정 일정: `lab-updates.js`의 `labEvents` 배열에 `{ title, date, location, url }`을 추가한다. date는 `YYYY-MM-DD`, url·location은 선택값이다. 확정된 공개 일정만 등록한다. 한국 시간의 오늘을 포함한 미래 일정만 날짜순 최대 3건 표시하며 배열이 비면 빈 상태 안내를 표시한다. 과거 항목은 데이터에 남지만 메인에서 제외된다.
- 활동은 관리자 페이지에서 게시합니다. 홈 소식과 예정 일정은 기존 정적 파일 수정 방식입니다. 내부 이슈나 비공개 일정은 공개 저장소에 넣지 않습니다.

## 구성원 화면 구성

데스크톱은 인물 정보·기술 스택·관심 분야를 나란히 배치한 한 열 카드이며, 모바일은 세로로 쌓습니다. 재학생/졸업생 탭의 인원수는 members.js가 실제 카드에서 계산합니다. 탭은 고정하지 않으며 사진·이름 영역 전체가 프로필 링크이며 hover/키보드 포커스를 표시합니다. 별도 이동 버튼은 없습니다. PC 목록에서는 기술 태그와 관심 분야를 각각 한 줄로 요약하고 너비를 넘는 태그는 통째로 숨깁니다. 전체 내용은 상세와 검색 대상에 유지합니다.

구성원 찾기는 이름·기술 스택·관심 분야의 부분 문자열을 검색합니다. 공백으로 나눈 단어를 모두 포함해야 하며 영문 대소문자는 구분하지 않습니다. 현재 탭 안에서 검색하고 결과 수·빈 상태를 안내합니다. 검색어는 URL의 q에 보존하며 지우기 버튼/초기화/Escape로 해제합니다. JavaScript가 비활성화되면 검색 UI를 숨기고 기본 목록을 제공합니다.

기술 스택은 언어·프레임워크·플랫폼·AI 도구·버전 관리 기술을 표시하며 IDE(Visual Studio, VS Code)는 제외합니다. Git/GitHub는 기술 항목에서 Git으로 표시하고 실제 GitHub 링크와 활동 설명은 유지합니다. 목록과 상세에 같은 기준을 적용합니다.

개인 상세 경력·활동은 진행 중 우선, 종료된 활동은 마지막 확인 연월의 최신순으로 배치합니다. 날짜 없는 항목은 후순위이며 기존 activity-N 앵커는 재번호하지 않습니다. 역할이 바뀌어도 참여가 이어지는 항목은 전체 참여 기간과 역할별 임기를 구분합니다.

최수연 상세는 `member-choi-suyeon.html`입니다. 사용자 제공 기술·관심 분야와 대학 연구실 활동 1건을 반영했습니다. 사용자가 확인한 컴퓨터공학과 2학년·1기를 표시하며, 입학 연도 2025는 정렬 데이터에만 보존합니다. 활동 기간·포트폴리오는 미제공으로 생략하며, 공통 GitHub 항목은 —로 표시합니다.

PC 화면(1000px 이상)은 최대 1200px의 중앙 레이아웃과 88px 헤더를 사용합니다. 하위 페이지에는 현재 위치를 표시하고, 실제 하위 분류가 있는 경우에만 왼쪽 카테고리 메뉴를 표시합니다. 본문 목차나 개별 활동은 카테고리 메뉴에 넣지 않습니다. 본문은 주로 14–15px, 페이지 제목은 28px, 홈 대표 제목은 32px입니다. 구성원은 사진/학적과 기술/관심 분야를 나란히 배치하며, 사진은 88×110px(1000–1199px는 80×100px)입니다. PC에서는 재학생/졸업생 및 활동 유형을 왼쪽 카테고리 메뉴에서 선택하며, 중복 본문 탭은 숨깁니다. 활동은 한 열, 문의는 2×2로 표시합니다. 세부 메뉴는 구성원 탭과 선택 상태를 동기화합니다. 사용자 요청에 따라 모바일 UI 개선은 후속 작업으로 남겼습니다.

홈은 연구·구성원·대표 수상·활동·지도교수의 다섯 대표 카드로 구성합니다. 긴 설명은 상세 페이지에서 제공하며 하단에는 Notice & News와 Calendar를 두 열로 표시합니다. 공통 푸터는 연구실 로고·정식 명칭·위치·저작권 정보를 중앙 정렬로 제공합니다. 미니 뉴스는 최대 3건을 유지하며 확인된 소식만 등록합니다. 일정은 `lab-updates.js`의 공개 일정 데이터를 사용합니다.

PC 목록은 실제 너비에 온전히 들어가는 태그만 표시합니다. 리사이즈·탭·검색·폰트 로드 때 재계산하며 전체 내용은 검색과 상세에 보존합니다. 개인 상세와 교수는 이름을 상단 왼쪽에 두고 사진·정보를 좌우로 배치합니다. 사진은 220×275px(좁은 PC 200×250px)입니다. 개인 상세는 이름 아래 구분선, 교수는 프로필 끝·학력 위 구분선을 사용합니다.

## 계정과 사이트 관리

모든 페이지 상단의 로그인 링크에서 `account.html`로 이동합니다. 회원가입 후 관리자가 기존 구성원 프로필을 연결하면 본인 프로필 수정과 활동 제출을 사용할 수 있습니다. 새 활동은 관리자 승인 후 공개됩니다.

관리자는 구성원 승인, 사이트 콘텐츠, 운영 설정 탭을 사용합니다. 문구·링크·사진을 사이트에서 저장하며 활동 승인·반려·수정·삭제·복구도 할 수 있습니다. 기능 설정은 DB 권한에도 적용됩니다. 상세 운영·가입 설정·권한·복구·검증 절차는 [SUPABASE_SETUP.md](SUPABASE_SETUP.md)를 참조합니다.

현재 변경을 처음 공개하려면 사이트 파일 배포가 필요합니다. 이후 DB에 저장하는 콘텐츠는 Git push나 재배포 없이 반영됩니다. 레이아웃·메타데이터·새 페이지 구조는 소스 수정 대상입니다.
